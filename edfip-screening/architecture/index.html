EDFIP · Dexta Synergy Services · Proposed architecture

One platform Emeraid hosts. Institutions are onboarded and licensed. Fineract is core banking. Odoo is the product.

Commercialisable multi-tenant SaaS: deploy once, onboard, sell configurable packs. Staff work in Odoo. FastAPI runs beside Odoo on the same environment. Security sits on every plane.

SaaS
Do not deploy a new EDFIP for each MFI or cooperative. Emeraid Super Admin onboards the institution, turns on the pack they paid for, and their staff use only that portion. Suspend locks login and keeps data. A giant tenant may later get a dedicated store — still on Emeraid’s hosting.
Odoo Operating core. System Administration, staff UI, CRM, KYC, branches, VSLA, PayGo, agency float.
Apache Fineract Money core. Core banking: loans, savings, schedules, balances, GL. API only. No Mifos UI.
FastAPI Sibling API on the same environment. ID map, idempotency, webhooks. Not inside Odoo. Not a third bank.
Flutter Field Android (offline) and customer Android. Talks to FastAPI only.

1. SaaS — onboard, do not reinstall

One Emeraid-hosted platform. Configurable packs. Licence enforced in Odoo, FastAPI, and Fineract, or it is fake.

Normal product

1 Super Admin creates the institution in System Administration.
2 Turns on the pack (MFI, cooperative, VSLA, PayGo — or à la carte). Packs can change later.
3 Staff log in and never see what they did not buy. FastAPI refuses those APIs.
4 Suspend = lock login, keep data. Restore when the licence is current.

Example packs

Not on-prem. Not a zip file per customer. Dedicated database later is still Emeraid-operated SaaS.

2. System architecture

Two front doors. Staff open Odoo. Field, customer, USSD and partners open FastAPI. Every naira still posts in Fineract.

Channels

Staff webOdoo UI — credit, CRM, finance, admin
Flutter fieldOffline outbox, collections, KYC capture
Flutter customerBalances, repay, PayGo status
USSD · partners · OEMPayments, bureaus, token providers
Staff stay in Odoo · Mobile / USSD / partners enter FastAPI · Nginx TLS at the edge
Odoo · operating core Institution onboarding · branch access engine · CRM · KYC · VSLA share-out · coop shares · PayGo / OEM workflow · agency float · portal
FastAPI · orchestration EDFIP REST · Odoo IDs ↔ Fineract IDs · tenant + branch scope · idempotent money commands · webhooks · offline sync · reconciliation
Identity OIDC · MFA · RBAC · tenant and branch claims on the token
Money commands only: Odoo or Flutter → FastAPI → Fineract · FastAPI does not write either database
Apache Fineract · core banking (money core) Products · clients · savings · loans · schedules · repayments · GL · office tree mapped from Odoo branches
Reporting Financial figures from Fineract. Operational figures from Odoo. Combined reports join IDs — never shared table writes.

FastAPI is a sibling process on the same environment as Odoo (Nginx / → Odoo, /api → FastAPI). It is not an Odoo addon and not a wall in front of staff screens.

Two admin worlds

Emeraid Super Admin System Administration. Onboard, licence, suspend. Never processing Branch A loans.

Platform connectors (OIDC, SMS, payments, OEMs) are configured once. Each institution only gets the modules on its licence.

4. Institution onboarding and branch access

Emeraid onboards the institution in Odoo. Inside that institution, staff are granted branches. The same tree is copied to Fineract as offices so core banking cannot leak.

One tenant in Odoo

Institution · e.g. Greenlight MFI Module pack · branding · licence · Institution Admin (all branches)
Branch A · GarkiCredit officer, teller — see Garki only
Branch B · WuseCredit officer, teller — see Wuse only

Mapped 1:1: Odoo institution → Fineract tenant. Odoo branch → Fineract office.

Branch access engine — three layers

Odoo Record rules. Staff cannot open another branch’s CRM, groups, tills or assets. This is where admins assign access.
FastAPI Token carries institution + branch IDs. Flutter or partner calls outside that scope are rejected.
Fineract User bound to the mapped office. Loans, savings and GL postings cannot land in the wrong branch.
